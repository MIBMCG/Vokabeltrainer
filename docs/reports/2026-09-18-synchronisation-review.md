## Important findings — must fix before accepting Task 9

1. **Normal My Drive folders cannot sync or join.** `src/trainer/sync/drive.js:245` and `:386` require the dataset folder to have zero parents. The adapter creates a normal folder without specifying `parents`; Google places that folder in My Drive, whose root ID is its parent. The synthetic adapter uses `parents: []`, hiding the incompatibility. A focused probe changed the created folder metadata to `parents: ['my-drive-root']`; `sync()` rejected it with `binding`. Validate the selected folder's identity/app/dataset, without requiring a real folder to be parentless; fix the fake and cover both create/sync and join. Evidence: `src/drive/client.js:255`; [official Files resource, parents](https://developers.google.com/workspace/drive/api/reference/rest/v3/files#File).

2. **Join can silently discard a successfully committed concurrent local change.** `src/trainer/sync/drive.js:396` computes `sameDataset/nonempty` only once, before the CAS loop; `:415` then replaces the current ledger/outbox using that stale decision on every retry. A focused probe started from an empty setup, committed a new local profile before the first join CAS commit, and forced its normal stale retry. Join then succeeded and deleted the new profile and its outbox entry. Recompute the dataset identity and emptiness guard inside the `mutate` transform on every attempt; reject with `not-ready/stale` if the local stand became nonempty. This is a Task 9 preservation bug even though intentional nonempty joining is deferred.

3. **A missing pre-read version can poison the verified-version cache.** `src/trainer/sync/drive.js:199` compares versions only when both exist, but `:203` caches the post-read version even when the pre-read version was absent. If JSON changes after the content read, an old hash is associated with the new version; subsequent sync skips the changed file indefinitely. Focused reproduction: omit the before-version once, return old JSON, modify the stored JSON and advance version to `2` before the after-metadata response; both that sync and the next report `synced` while local and remote contents differ. Cache a version/hash association only when both bracketing versions exist and agree; otherwise retain no cache entry and re-read on future syncs.

4. **Transient read failure on a cached known file leaves permanent quarantine.** `src/trainer/sync/drive.js:495` skips successfully verified cached files without clearing their quarantine entries, while the catch at `:523` quarantines even transient network/auth failures. A focused probe made one metadata read of a known epoch fail with `network`. On retry fresh metadata succeeds and the version/hash matches, but the file is skipped and the old quarantine remains; the retry fails with `invalid` permanently. Do not persist transport/auth failures as malformed-content quarantine, and/or explicitly clear a resolved transport quarantine after an authenticated identity/version/hash verification. Cover the cached-file branch, not only a previously unverified packet.

5. **Packet identity collisions escape detection across sync runs.** `src/trainer/sync/drive.js:480` creates a new packet-ID map for each download, and `:495` omits cached known packets from it. A new file with the same `packetId` but different valid events is accepted when the first packet is cached. The focused probe synced packet `same-packet`, added a second file using `same-packet` with another preference event, then synced successfully and imported both. Maintain/derive an integrity index for logical packet ID → canonical content hash across known files and sessions; reject differing content even when one physical file is skipped.

6. **Interrupted initial publication can produce two discoverable folders for one dataset identity.** `src/trainer/sync/drive.js:330`–`:358` creates all setup IDs only in RAM, and binding is persisted after descriptor upload succeeds. A lost descriptor-upload response can occur after the descriptor is stored: discovery then offers a complete bootstrap, contrary to the report's claim that the orphan is not offered. Retrying `createDataset` allocates another folder for the same descriptor/dataset ID. A focused probe reproduced two discovery results with the same dataset identity after precisely this failure. Devices choosing different folders then exchange different packet streams despite sharing the logical dataset ID. Persist and resume the exact setup publication job/IDs before network writes, with backward-compatible state normalization; do not treat this as merely cosmetic orphan cleanup. The approved stable-identity, immutable-publication and retry behavior requires a recoverable result even though the initial state schema omitted a setup-job field.

7. **Local changes leave a false fully-synced status.** `src/trainer/sync/drive.js:727` returns a cached status that is updated only by sync operations. After a successful sync, a committed local revision adds an outbox entry while `getStatus()` still returns `phase: 'synced', pendingCount: 0`. This was reproduced with a normal `commands.revise`. Reconcile status/counts against current committed state on reads and notify the status consumer when new local work becomes pending; a scheduled sync up to ten seconds later is not truthful immediate status integration.

8. **The scheduler can postpone changes indefinitely beyond ten seconds.** `src/trainer/sync/scheduler.js:81` resets the ten-second timer on every `changed()`, and `schedule` cancels the existing deadline. The contract says changes are bundled after at most ten seconds. A focused fake-clock probe with changes at 9 and 18 seconds moved the deadline to 19 and 28 seconds without a sync. Preserve the earliest pending deadline/use the injected clock, and ensure completion of an in-flight sync cannot replace an earlier change deadline with a later one. Cover repeated changes during the window, not just a single change.

9. **One quarantined remote packet prevents every independent local upload.** `src/trainer/sync/drive.js:603` throws after recording any remote file problem; `:684` awaits that operation before preparing or sending any pending packets. Thus a persistent malformed/version-invalid/dependency-missing packet blocks all outgoing local changes, including unrelated profiles, on every attempt. The contract explicitly limits quarantine to affected data and allows unaffected data to continue syncing. Preserve/report per-file problems, merge valid downloads, and safely upload independent local packets before returning the visible incomplete/error status. Fatal binding/account errors must still stop the whole operation. This follows directly from control flow; no broad test rerun was needed.
